# 고용24 경비 일자리 검색/알림 서비스 작업 계획서

작성일: 2026-06-17

## 1. 목표

고용24 채용정보에서 `주말경비`, `야간경비`, `경비원`, `시설경비`, `아파트 경비` 같은 키워드로 일자리를 하루 2회 자동 검색하고, 결과를 웹페이지와 Slack/Discord 채널에 보여주는 서비스를 만든다.

핵심 목표는 다음과 같다.

- 고용24 채용정보를 안정적으로 조회한다.
- 이미 확인한 공고는 다시 알리지 않는다.
- 사용자가 보기 쉬운 웹 목록을 제공한다.
- 새 공고가 있을 때 Slack 또는 Discord로 요약 알림을 보낸다.
- 검색 키워드, 지역, 근무시간 조건을 코드 수정 없이 설정할 수 있게 한다.

## 2. 공식 자료 확인

고용24 채용정보 상세검색 화면은 검색어, 지역, 경력, 고용형태, 근무형태, 격일근무, 교대근무, 근무시간 등 조건을 제공한다.

- 상세검색 화면: https://www.work24.go.kr/wk/a/b/1200/retriveDtlEmpSrchList.do

고용24는 채용정보 Open API도 제공한다. API는 HTTP 기반이며 XML 응답을 반환하고, 사용하려면 고용24 기업회원 가입 후 인증키 신청/심사가 필요하다.

중요 제한:

- 개인회원으로는 채용행사, 공채속보, 공채기업정보 API만 이용할 수 있다.
- 이 서비스에 필요한 `채용정보목록`, `채용정보상세` API는 개인회원으로 신청할 수 없다.
- 발급받은 개인회원 키로 채용정보 목록 API를 검증한 결과, `<GO24><error>개인회원은 사용할 수 없는 OPEN-API입니다.</error></GO24>` 응답이 내려왔다.
- 따라서 현재 MVP 기본 경로는 공식 채용정보 API가 아니라 `개인 운영 수집 경로`로 확정한다.

- Open API 소개: https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do
- 채용정보 API 문서: https://www.work24.go.kr/cm/e/a/0110/selectOpenApiSvcInfo.do?apiSvcId=000000000000000000000000000060&upprApiSvcId=000000000000000000000000000059&fullApiSvcId=000000000000000000000000000000%5E000000000000000000000000000001
- 공공데이터포털 설명: https://www.data.go.kr/data/3038225/openapi.do

## 3. 권장 구현 방향

현재 1순위는 `고용24 상세검색 페이지 기반 개인 운영 수집`이다.

발급받은 개인회원 키는 채용정보 목록 API에서 권한 오류가 확인됐다. 공식 API 기반 구현은 고용24 기업회원 또는 채용정보 API 권한이 있는 키가 확보될 때까지 보류하고, 사용자가 직접 접근 가능한 상세검색 화면을 낮은 빈도로 조회해 결과를 정리하는 방식으로 MVP를 만든다.

구현 경로는 2개로 분리한다.

| 경로 | 사용 조건 | 장점 | 한계 |
| --- | --- | --- | --- |
| A. 기업회원 API 경로 | 고용24 기업회원 인증키 확보 | 안정적, XML 구조 명확, 중복 판단 쉬움 | 개인회원 불가, 인증키 심사 필요 |
| B. 개인 운영 수집 경로 | 개인회원 또는 비로그인 화면 접근 | 바로 시작 가능, 하루 2회 저빈도 운영 가능 | 화면 구조 변경 리스크, 이용 조건 검토 필요 |

권장 순서:

1. B 경로로 웹페이지/알림 MVP를 만든다.
2. 데이터 수집부는 `source adapter`로 분리해 둔다.
3. 나중에 기업회원 또는 채용정보 API 권한이 있는 키가 생기면 A 경로 어댑터를 추가한다.

## 4. 주요 기능 범위

### 4.1 검색 조건 관리

설정 파일 또는 관리자 화면에서 다음 값을 관리한다.

- 검색 키워드: `주말경비`, `야간경비`, `경비원`, `시설경비`, `건물경비`, `아파트 경비`, `보안`, `당직`
- 제외 키워드: `요양보호사`, `간병`, `청소만`, `주차관리만` 등
- 지역: 예시 `서울`, `경기`, `인천` 또는 API 지역 코드
- 등록일 범위: 기본 `오늘` 또는 `최근 3일`
- 근무시간: 야간 후보는 `저녁`, `새벽`, `저녁~새벽` 코드 우선 검토
- 정렬: 등록일 최신순
- 출력 건수: 키워드별 최대 100건

### 4.2 데이터 수집

데이터 수집은 `source adapter` 구조로 만든다.

공통 인터페이스:

```text
searchJobs(query, options) -> Job[]
getJobDetail(jobId) -> JobDetail
```

#### 0단계: 발급 키 검증

키는 절대 코드나 문서에 직접 적지 않고 환경 변수로만 넣는다.

검증 결과:

- 검증일: 2026-06-17
- 대상: 채용정보 목록 API
- 결과: 실패
- 오류: `개인회원은 사용할 수 없는 OPEN-API입니다.`
- 판정: 현재 키로는 채용정보 목록/상세 API를 사용할 수 없다.

검증 요청:

```text
GET https://www.work24.go.kr/cm/openApi/call/wk/callOpenApiSvcInfo210L01.do
  ?authKey={WORK24_AUTH_KEY}
  &callTp=L
  &returnType=XML
  &startPage=1
  &display=10
  &keyword=경비원
  &sortOrderBy=DESC
```

판정 기준:

- 성공: XML에 `<wantedRoot>`, `<total>`, `<wanted>` 항목이 내려온다.
- 권한 제한: 인증키 오류, 서비스 미신청, 권한 없음, 개인회원 제한 메시지가 내려온다.
- 일시 오류: 네트워크 오류, 점검, 5xx 응답이면 재시도 후 판단한다.

검증 결과 저장:

- 성공/실패 여부
- HTTP 상태 코드
- 응답의 최상위 XML 태그
- 오류 메시지
- 검증 시각

#### B 경로: 개인 운영 수집

개인회원 상태에서는 고용24 상세검색 화면을 기준으로 검색한다.

수집 방식 후보:

- 검색 조건을 포함한 URL 또는 폼 요청을 분석해 HTTP 요청으로 결과를 가져온다.
- 화면이 JavaScript 기반으로만 결과를 렌더링하면 Playwright로 브라우저 자동화를 사용한다.
- 하루 2회, 키워드 수 제한, 요청 간 대기 시간을 두어 저빈도로 운영한다.
- 로그인, 우회, 보안장치 회피가 필요한 방식은 사용하지 않는다.

개인 운영 수집에서 저장할 최소 필드:

- 원문 공고 URL
- 채용제목
- 회사명
- 근무지역
- 급여
- 근무형태
- 등록일
- 마감일
- 검색 키워드
- 수집 시각

중복 판단:

- 1순위: 화면에서 확인 가능한 구인인증번호 또는 공고 ID
- 2순위: 원문 URL
- 3순위: `회사명 + 제목 + 지역 + 마감일` 해시

#### A 경로: 발급 키 기반 API

기업회원 또는 채용정보 API 권한이 있는 인증키가 확보되면 고용24 채용정보 API 목록 요청을 사용한다.

기본 요청 형태:

```text
GET https://www.work24.go.kr/cm/openApi/call/wk/callOpenApiSvcInfo210L01.do
  ?authKey={WORK24_AUTH_KEY}
  &callTp=L
  &returnType=XML
  &startPage=1
  &display=100
  &keyword={검색어}
  &sortOrderBy=DESC
```

필요 시 추가 파라미터:

- `region`: 근무지역 코드
- `occupation`: 직종 코드
- `regDate`: `D-0`, `D-3`, `W-1` 등
- `workHrCd`: 근무시간 코드
- `holidayTp`: 근무형태 코드
- `empTp`: 고용형태 코드
- `empTpGb`: 상용직/일용직

### 4.3 정규화 및 필터링

수집 결과를 내부 공고 모델로 정규화한다.

필수 필드:

- `sourceId`: 구인인증번호, 공고 ID, URL, 해시 중 하나
- `wantedAuthNo`: 고용24 구인인증번호, API 또는 화면에서 확인 가능할 때 저장
- `title`: 채용제목
- `company`: 회사명
- `region`: 근무지역
- `salary`: 급여
- `holidayType`: 근무형태
- `career`: 경력
- `regDate`: 등록일
- `closeDate`: 마감일
- `url`: 원문 공고 URL
- `matchedKeywords`: 매칭된 검색어
- `score`: 우선순위 점수

필터링 규칙:

- 제목/회사명/지역/근무형태/급여가 비어 있어도 저장하되 UI에서 `정보 없음`으로 표시한다.
- 제외 키워드가 제목 또는 직무내용에 있으면 숨긴다.
- `야간`, `저녁`, `새벽`, `당직`, `격일`, `24시간`, `주말`, `토요일`, `일요일`이 있으면 우선순위를 올린다.
- `sourceId`가 같은 공고는 하나로 합친다.

### 4.4 저장소

초기 MVP는 SQLite를 사용한다.

테이블 후보:

- `jobs`: 현재/과거 공고 원본 및 정규화 결과
- `job_matches`: 공고별 키워드 매칭 이력
- `runs`: 검색 실행 기록
- `notifications`: Slack/Discord 발송 이력
- `settings`: 키워드, 제외어, 지역, 스케줄 설정

중복 알림 방지:

- `sourceId + channel` 기준으로 이미 발송한 공고는 재발송하지 않는다.
- 기존 공고라도 마감일, 급여, 제목이 바뀌면 웹페이지에는 갱신 표시를 한다.
- 알림은 새 공고만 보낸다.

### 4.5 웹페이지

첫 화면은 바로 공고 목록을 보여준다.

필요 화면:

- 대시보드: 최신 공고, 오늘 새 공고 수, 마지막 검색 시각
- 공고 목록: 키워드, 지역, 근무시간, 급여, 등록일, 마감일 필터
- 공고 상세: API 데이터와 원문 링크
- 검색 설정: 키워드/제외어/지역/알림 채널 설정
- 실행 이력: 최근 검색 성공/실패, 수집 건수, 신규 건수

목록 UI 우선순위:

- 모바일에서도 읽기 쉬운 카드형 목록
- 데스크톱에서는 표 형태와 필터 사이드바
- 원문 공고로 바로 이동하는 버튼
- `야간`, `주말`, `격일`, `신규`, `마감임박` 배지

### 4.6 Slack/Discord 알림

Slack은 Incoming Webhook 또는 Slack Bot Token 중 하나를 사용한다.

Discord는 Webhook URL을 사용한다.

알림 메시지 예시:

```text
[경비 일자리] 새 공고 3건

1. 야간 경비원 모집 - 서울 강남구
   회사: 예시관리
   급여: 월급 250만원
   근무: 주 5일 / 야간
   마감: 2026-06-30
   링크: https://...
```

발송 정책:

- 하루 2회 정기 검색 후 새 공고가 있을 때만 발송한다.
- 새 공고가 없으면 기본적으로 발송하지 않는다.
- 원하면 `새 공고 없음` 요약 메시지를 별도 옵션으로 둔다.
- 한 번에 너무 많으면 상위 10건만 보내고 웹페이지 링크를 붙인다.

## 5. 스케줄링

기본 스케줄은 한국시간 기준 하루 2회로 둔다.

- 오전 검색: 08:00 KST
- 오후 검색: 18:00 KST

배포 방식별 선택지:

- 서버 배포: cron 또는 systemd timer
- Docker 배포: 컨테이너 내부 cron보다 호스트 cron 또는 스케줄러 권장
- GitHub Actions: 공개 저장소/비밀키 관리에 주의, 웹서비스 상시 제공에는 부적합
- Windows PC 상시 실행: 작업 스케줄러 사용

권장 운영안:

- 웹페이지가 필요하면 작은 VPS 또는 NAS/Docker 서버에 배포한다.
- 알림만 필요하면 GitHub Actions 또는 Windows 작업 스케줄러로도 시작 가능하다.

## 6. 기술 스택 제안

저장소가 비어 있으므로 단순하고 유지보수 쉬운 구성을 제안한다.

- 런타임: Node.js 22 LTS
- 웹 프레임워크: Next.js 또는 Remix
- 수집 작업: Node.js 서버 내부 job runner 또는 별도 CLI
- DB: SQLite, 추후 PostgreSQL 전환 가능
- XML 파싱: `fast-xml-parser`
- 스케줄: `node-cron` 또는 운영 환경 cron
- UI: React + Tailwind CSS
- 배포: Docker

대안:

- Python/FastAPI + Jinja/HTMX: 수집 로직 중심이면 더 가볍다.
- Spring Boot: 장기 운영/관리자 기능이 커질 때 적합하다.

MVP는 `Next.js + SQLite + Docker`가 가장 빠르다.

## 8. 구현 단계

### 1단계: 프로젝트 기반 구성

- Next.js 프로젝트 생성
- SQLite 연결
- 환경 변수 로딩
- 기본 레이아웃과 공고 목록 화면 생성

산출물:

- 실행 가능한 웹앱
- 빈 공고 목록 화면
- Dockerfile 초안

### 2단계: 개인 운영 수집기 구현

현재 기본 구현 단계다.

- 상세검색 페이지 요청 구조 확인
- 검색 키워드별 결과 목록 수집
- 필요 시 Playwright 브라우저 자동화 적용
- 수집 결과를 내부 모델로 변환
- 키워드별 검색 실행 CLI 작성
- 빈 결과/타임아웃/화면 구조 변경 처리

산출물:

- `npm run fetch:jobs` 같은 수동 실행 명령
- 샘플 검색 결과 저장

### 2-1단계: API 어댑터

기업회원 또는 채용정보 API 권한이 있는 키가 확보됐을 때 진행한다.

- 인증키 환경 변수 연결
- 채용정보 목록 API 권한 검증 CLI 작성
- 채용정보 목록 XML 호출
- XML 파싱 및 내부 모델 변환
- API 오류/빈 결과/타임아웃 처리

산출물:

- `SOURCE_MODE=api`로 전환 가능한 API 수집기

### 3단계: 저장/중복 제거

- `jobs`, `runs`, `notifications` 테이블 생성
- `sourceId` 기준 upsert
- 신규 공고와 기존 공고 구분
- 검색 실행 로그 저장

산출물:

- 반복 실행해도 중복 저장/중복 알림이 발생하지 않는 수집기

### 4단계: 웹 UI 구현

- 최신 공고 목록
- 키워드/지역/신규/마감임박 필터
- 공고 상세 또는 원문 링크
- 마지막 검색 시각과 신규 공고 수 표시

산출물:

- 실제 수집 데이터 기반 웹페이지

### 5단계: Slack/Discord 알림

- Slack Webhook 발송
- Discord Webhook 발송
- 신규 공고만 알림
- 발송 실패 재시도 및 실패 로그

산출물:

- 채널에 새 공고 요약 메시지 발송

### 6단계: 스케줄링/배포

- 하루 2회 자동 실행
- Docker Compose 구성
- 운영 로그 확인 방법 문서화
- 백업/복구 방법 문서화

산출물:

- 서버 또는 PC에서 자동 검색/알림 운영 가능

## 9. 테스트 계획

단위 테스트:

- XML 응답 파싱
- 키워드 매칭
- 제외어 필터링
- 중복 제거
- 알림 메시지 포맷

통합 테스트:

- 실제 상세검색 페이지 수집 1회
- 기업회원 인증키가 있을 경우 실제 API 호출 1회
- SQLite 저장 확인
- 웹 목록 렌더링 확인
- Slack/Discord 테스트 채널 발송 확인

운영 테스트:

- 같은 검색을 2번 실행해도 알림이 중복되지 않는지 확인
- API 장애 시 웹페이지가 기존 데이터를 보여주는지 확인
- 키워드 추가 후 다음 실행부터 반영되는지 확인

## 10. 리스크와 대응

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| Open API 인증키 발급 지연 | 개발 초기 실제 수집 지연 | 샘플 XML과 수동 입력 데이터로 UI/DB 먼저 개발 |
| 발급 키가 채용정보 API 권한을 갖지 않음 | 공식 API 수집 불가 | 확인 완료. 개인 운영 수집 경로로 진행 |
| 상세검색 화면 구조 변경 | 수집 실패 | 수집 어댑터 분리, 실패 로그, 선택자 테스트 추가 |
| 과도한 자동 조회로 접근 제한 | 검색 중단 | 하루 2회 저빈도, 요청 간 대기, 키워드 수 제한 |
| API 응답 XML 구조 변경 | 파싱 실패 | 파서 테스트와 실패 로그 추가 |
| 키워드 결과가 너무 넓음 | 관련 없는 공고 증가 | 제외어, 점수화, 근무시간 코드 필터 추가 |
| 같은 공고가 여러 키워드에 걸림 | 중복 표시/알림 | `wantedAuthNo` 기준 병합 |
| Slack/Discord 장애 | 알림 누락 | `notifications` 실패 상태 저장 후 재시도 |
| 공공데이터 이용 조건 | 서비스 공개 범위 제한 | 출처 표시, 비상업/변경금지 조건 검토 후 운영 |

## 11. 미리 결정해야 할 사항

- 검색 대상 지역: 전국인지, 수도권인지, 특정 시군구인지
- 알림 채널: Slack, Discord, 둘 다인지
- 알림 시간: 08:00/18:00 KST로 확정할지
- 새 공고가 없을 때도 메시지를 보낼지
- 웹페이지 접근 권한: 공개, 비밀번호 보호, 내부망 전용 중 선택
- 기업회원 또는 채용정보 API 권한이 있는 키를 추가로 확보할 수 있는지
- 개인 운영 수집 방식이 사용 목적과 이용 조건에 맞는지

## 12. MVP 완료 기준

- 수동 실행으로 고용24 상세검색에서 경비 관련 공고를 가져온다.
- 공고가 SQLite에 저장되고 중복 저장되지 않는다.
- 웹페이지에서 최신 공고를 볼 수 있다.
- 하루 2회 자동 검색이 실행된다.
- 새 공고가 있으면 Slack 또는 Discord에 한 번만 알림이 간다.
- 실패 로그를 보고 원인을 확인할 수 있다.
